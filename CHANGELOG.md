# Changelog

## 5.7.0 - Midia Final Submission Patch

Финальный точечный patch без изменения 12-классового clinical/ML core:

- проект и README оформлены для команды **«Мидия»** по требованиям итоговой сдачи;
- поле ФИО по умолчанию пустое, placeholder — `Введите ФИО пациента`;
- deterministic PDF/TXT parser стал мягче: сохраняет клинический текст, разделяет жалобы, анамнез и препараты по явным секциям и смысловым сигналам, не превращая дозировки/длительность терапии в лабораторные значения;
- добавлен опциональный локальный Ollama-parser клинического контекста с редактированием результата врачом и fallback на обычный parser;
- ФИО и прямые идентификаторы удаляются перед AI-структурированием;
- добавлен Figma-aligned visual theme: мягкий фон, фиолетово-синяя палитра и бренд команды; медицинская логика и рабочие кнопки не менялись;
- PDF отчёт приведён к той же визуальной системе и брендирован `Meditron · команда «Мидия»`;
- интегрирован воспроизводимый `research_audit/` и уточнена архитектура семи вычислительных слоёв;
- добавлен финальный комплект презентации/речи/плана и Docker-инструкции.

## 5.6.0 - Parser Boundaries & Report Layers Patch

Точечный patch без изменения 12-классового clinical/ML core:

- карточка пациента и итоговое резюме больше не нумеруются как аналитические слои;
- в PDF нумерация теперь строго соответствует 7 вычислительным слоям: нормализация, clinical, ML, uncertainty, causal, similar profiles, AI/RAG;
- расширено распознавание ФИО: `ФИО пациента`, варианты `Ф.И.О.`, `Patient name`, а также отдельные поля фамилия/имя/отчество;
- секции жалоб, анамнеза и препаратов теперь режутся по явным границам даже если PDF «сплющил» несколько полей в одну строку;
- добавлена фильтрация PDF-символов/служебного мусора;
- фразы из лекарственного/анамнестического текста больше не должны ошибочно превращаться в лабораторные значения (например, «принимала железо 3 месяца»);
- AI-ответ разделяется устойчивыми служебными маркерами; пациентский текст исключён из врачебной части и выводится только на последнем листе для пациента;
- AI-вкладка в UI показывает только врачебное объяснение, а пациентскую версию сохраняет для финальной страницы PDF.

## 5.5.0 - Interface Cleanup Patch

Точечный UX/import/report patch без изменения 12-классового clinical/ML core:

- верхняя панель: справочник, FAQ, служебные инструменты и выделенная кнопка нового пациента;
- беременность скрыта из обычного UI, но остаётся backend safety-gate;
- «Жалобы» и «Симптомы» объединены, отдельный `patient_priority` удалён;
- усилен PDF/TXT parser и фильтрация административного мусора;
- добавлен свободный TXT-import;
- автоматическая подстановка единиц измерения при ручном вводе;
- усилено предупреждение о ручной проверке импортированных данных;
- разговорный режим дополнен ML-рейтингом и упрощёнными причинными связями;
- visible ML ranking сохранён в ML-вкладке, сырые scores свёрнуты;
- case-base и books перенесены в верхние «Инструменты»;
- МКБ-10 оставлен в одном PDF-разделе;
- AI Markdown корректно рендерится в PDF, а короткое patient explanation выводится отдельно.


## 5.4.0 - Human-Centered Patch

Точечный human-centered UX patch без изменения 12-классового ML/clinical core:

- добавлено необязательное поле «Что сейчас больше всего беспокоит пациента?»;
- это поле не влияет на ML/rules, не передаётся LLM и используется как «голос пациента» в разговорном режиме и PDF;
- добавлен «Режим разговора с пациентом» без ML-жаргона: факты, неопределённость, смысл следующего шага;
- «Главное» превращено в 30-секундный врачебный brief;
- добавлена нейтральная структура разговора: выслушать -> показать факты -> обозначить неопределённость -> объяснить следующий шаг -> проверить понимание;
- AI по-прежнему не симулирует эмпатию, не сообщает плохие новости и не принимает решение;
- `patient_priority` явно исключён из контекста, отправляемого локальной LLM;
- PDF дополнен главным вопросом пациента и вопросами для совместного обсуждения;
- добавлены `HUMAN_CENTERED_VISION.md` и `DOCTOR_PATIENT_SCENARIO.md` для продуктовой/идейной защиты.
